# miles design-directions

List the generated design directions for the active site. Porcelain, HEADLESS (listing never needs a browser).

```bash
miles design-directions [--json]
```

```json
{
  "phase": "design_directions_ready",
  "selectedDirectionId": null,
  "directions": [
    {
      "number": 1,
      "directionId": "hero-abc123",
      "name": "Warm Editorial",
      "status": "complete",
      "selectable": true,
      "previewUrl": "https://api.bymiles.ai/preview/slug/previews/hero-abc123/index.html",
      "screenshotCommand": "miles screenshot /preview/slug/previews/hero-abc123/index.html"
    }
  ]
}
```

`directionId` is the stable handle; `number` is what `build-site --design` takes. `selectable: false` directions (failed/cancelled/incomplete) must not be offered to the user.

Directions are generated by the conversation (brief approval triggers generation), not by this verb. If none exist yet, the response says so with the current phase — continue with `say` or `wait-job`.

## Judgment

- Inspect before recommending: with a connected dashboard, the visible canvas is the primary review surface; otherwise `miles screenshot` each `previewUrl` and view the images. Only claim visual inspection when something actually loaded — if previews failed, say so and present names/URLs instead.
- Give the user a recommendation tied to their brief (visual hierarchy, tone match, layout quality, imagery, polish) plus one-line notes per direction, then let them choose. Do not pick silently unless the user delegated the choice.
- "Just give me options" integrations: stop here — screenshot, hand the files/URLs to the calling workflow, never build.
- None fit → `miles say "<what is wrong and what they want instead>"` to get new directions.

## Exit codes

`0` ok · `2` no active conversation · `1` failed.
